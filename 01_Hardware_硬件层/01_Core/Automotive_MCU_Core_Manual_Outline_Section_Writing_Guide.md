# 车规 MCU 内核手册大纲（含各节写作说明）

## 前言

### 目的
说明本文档的编写目标。应明确本手册用于定义内核架构、编程模型、异常与中断行为、保护机制、调试能力及软件使用约束，为芯片设计、底层软件、OS/MCAL、编译器适配、测试验证和现场问题分析提供统一依据。

### 适用范围
说明本文档覆盖的内容边界。应明确手册聚焦 CPU 内核及其直接相关的系统接口，不展开外设功能细节；如存在多个芯片型号或不同 cut/revision，应说明适用器件范围与版本范围。

### 目标读者
说明面向的使用对象，例如：芯片架构设计人员、底层驱动开发人员、AUTOSAR/OS 开发人员、编译器适配人员、测试验证人员、功能安全工程师、调试支持人员等。

### 文档约定
说明全文统一采用的术语、字体、符号、寄存器/位域命名规则、数值表示方式（十六进制/二进制）、伪代码风格、时序图说明方式，以及“必须/应当/可以”等措辞的强弱定义。

### 缩略语与术语
列出文中涉及的缩写与专业术语，例如 CPU、ISR、Trap、NMI、MPU、FPU、EndInit、上下文、特权级、可屏蔽中断、同步异常、异步异常等，并给出统一定义。

### 参考资料
列出与本手册相关的其他文档，并说明与本手册的关系，如：
- 芯片用户手册：描述整片器件级实现
- 安全手册：描述安全机制与使用假设
- BootROM / 启动手册：描述启动链路与 Boot 行为
- 调试与跟踪手册：描述外部调试模块细节
- Flash 编程手册：描述代码/数据存储的编程方式
- 寄存器参考手册：描述全部寄存器位级定义
- 勘误表：描述已知问题与规避方案

## 1. 内核概述

### 1.1 内核定位
说明该 CPU 内核在整片车规 MCU 中承担的角色，包括：实时控制、功能安全控制、主控计算、核间协同等；说明与对标内核（如 AURIX TC2xx 对应内核形态）的总体定位关系，以及该内核在产品线中的等级与应用场景。

### 1.2 关键特性
概述内核最核心的卖点与工程特征，建议包括：字长、指令集特征、流水线深度、实时响应能力、存储保护、特权机制、调试跟踪、低功耗能力、可选扩展（FPU/DSP/Cache/Lockstep）等。本节不追求细节，而是给出能力全景图。

### 1.3 内核框图
给出内核顶层框图，并说明各功能块的作用与相互关系。通常包括：执行流水线、寄存器文件、取指单元、Load/Store 单元、中断/异常接口、调试接口、Cache/本地存储接口、系统总线接口、保护单元等。

### 1.4 内核与系统的接口
说明内核不是孤立存在的，需要和芯片级模块配合。本节应说明内核与本地 RAM、Flash、总线矩阵、中断路由器、调试系统、安全监控模块、看门狗、复位控制器之间的接口边界、责任归属和可见行为。

### 1.5 内核实例与变体
如果产品存在单核/多核/锁步/不同性能档位，应说明哪些能力是公共架构特性，哪些是具体产品实现差异；可附变体矩阵，例如某型号是否带 FPU、是否带 D-Cache、是否支持锁步等。

## 2. 编程模型

### 2.1 程序员模型总览
从软件开发者视角介绍内核的可见资源：寄存器集合、程序计数器、状态寄存器、堆栈、异常入口、访问模式等。目的是让读者快速建立“写 C/汇编/启动代码时，CPU 对我开放了什么”的整体认知。

### 2.2 寄存器模型
详细说明程序员可见寄存器的分类、用途、访问限制和保存规则。建议按通用寄存器、特殊寄存器、控制/状态寄存器、异常信息寄存器、调试相关寄存器来组织，并说明哪些寄存器由硬件自动维护，哪些由软件主动保存与恢复。

### 2.3 数据类型与操作数宽度
说明内核原生支持的整数宽度、符号扩展规则、字节序、对齐要求、浮点数据类型（如有）、位操作粒度，以及指令对不同数据宽度的支持情况。

### 2.4 地址空间模型
说明内核看到的逻辑地址空间是如何划分的，例如代码区、数据区、系统寄存器区、外设区、共享存储区、本地存储区等；说明寻址范围、保留区、异常区，以及软件需要关注的关键边界。

### 2.5 寻址方式
说明指令支持的寻址方式及其工程意义，例如立即数寻址、寄存器寻址、基址+偏移寻址、PC 相对寻址、间接寻址等；可补充哪些寻址模式对性能或代码尺寸更有利。

### 2.6 指令执行模型
说明指令从取指、译码、执行到写回的大体流程，介绍顺序执行、分支、流水线暂停、异常打断、访存等待等行为。此处不必列全指令集，但应说明执行语义和可预期性。

### 2.7 调用约定概述
说明函数调用时参数传递、返回值返回、调用者/被调用者保存寄存器规则、栈帧建立方式、中断函数特殊约束等，为编译器适配、汇编插桩、裸机开发提供统一基础。

### 2.8 ABI / 编译器相关约束
说明软件工具链与架构之间的接口约束，例如：栈对齐要求、函数序言/结语规则、优化对寄存器使用的影响、中断函数声明方式、裸函数限制、内联汇编约束、调试信息与优化级组合的注意事项。

## 3. 特权级与运行模式

### 3.1 内核运行模式
说明内核支持的运行模式，如用户态、监督态、调试态、异常态、测试态等；明确各模式的进入条件、访问权限差异及使用场景。

### 3.2 模式切换机制
描述不同模式之间如何切换，例如通过异常、系统调用、调试请求、复位、特权指令等进入；并说明切换时硬件自动完成哪些动作、软件需要负责哪些动作。

### 3.3 特权指令访问规则
列出哪些指令只能在特权态执行，非特权执行时会发生什么；说明此规则在 OS、驱动和应用隔离中的意义。

### 3.4 访问限制规则
从“资源访问控制”的角度说明权限模型，例如用户态能否访问系统寄存器、能否修改中断屏蔽状态、能否访问特定地址空间、能否执行 Cache 维护或保护配置等。

### 3.5 系统寄存器访问机制
说明系统寄存器的读写方式、访问前置条件、同步要求、写后生效时机、是否需要屏障或解锁流程，以及错误访问的异常行为。

### 3.6 安全关键保护访问机制
如果有类似 EndInit/密码/key sequence/时间窗保护，应明确该机制的设计目的、保护对象、解锁-访问-重新上锁流程、超时或错误 key 的结果，以及推荐的软件封装方式。

## 4. 上下文管理

### 4.1 上下文模型概述
定义“上下文”包含哪些内容，如通用寄存器、状态寄存器、返回地址、堆栈指针、异常原因寄存器、浮点上下文等；说明为什么上下文管理是函数调用、中断响应、任务切换的基础。

### 4.2 硬件自动保存上下文
说明当中断/异常进入时，硬件自动压栈或写入的内容有哪些，保存顺序是什么，保存位置在哪里，是否支持最小现场保存或延迟保存。

### 4.3 软件保存上下文
说明哪些上下文必须由软件在 ISR、Trap、OS 切换例程中自行保存；要说明保存时机、恢复时机、不同场景下的差异，以及错误保存可能带来的问题。

### 4.4 栈模型
说明栈类型、用途、选择规则和对齐要求。例如主栈、进程栈、中断栈是否分离；不同模式/异常下使用哪个栈；栈增长方向；栈溢出风险与检测建议。

### 4.5 函数调用上下文切换
说明普通函数调用过程中的寄存器使用、返回地址保存、局部变量分配、递归影响，以及编译器生成代码与手写汇编应遵循的规则。

### 4.6 中断 / 异常上下文切换
说明中断或异常发生时，当前执行流如何被打断、现场如何保存、向量如何跳转、返回如何恢复；特别应交代对中断嵌套和故障恢复的影响。

### 4.7 中断嵌套上下文规则
说明在高优先级中断打断低优先级中断时，现场保存的层次关系、返回顺序、共享资源保护要求、栈深影响及编程注意事项。

### 4.8 上下文恢复规则
说明上下文恢复的合法顺序和限制，哪些寄存器必须最后恢复，返回指令如何判定返回目标与返回模式，以及恢复失败时会触发什么错误。

### 4.9 上下文管理错误场景
列举典型错误，例如栈损坏、返回地址破坏、上下文深度耗尽、错误异常返回、浮点上下文不匹配等，并说明检测方法和调试建议。

### 4.10 OS 适配注意事项
说明 RTOS/AUTOSAR OS 在任务切换、ISR2、系统调用、栈分配、临界区保护等方面必须满足的内核要求，为 OS 供应商或内部系统软件团队提供接口说明。

## 5. 复位、启动与上电行为

### 5.1 复位源概述
说明芯片支持的复位来源及其对内核的影响差异，如 POR、外部引脚复位、看门狗复位、软件复位、安全复位、调试复位等；应说明哪些是局部复位，哪些是系统级复位。

### 5.2 复位时序
描述从复位请求产生到内核真正进入复位状态，再到释放复位开始执行的完整时序。可配复位时序图，并说明关键采样点与软件可观察点。

### 5.3 复位后内核状态
说明复位释放后内核的初始状态，包括 PC、SP、状态寄存器、中断使能、保护状态、Cache/FPU/MPU 状态、调试状态等，确保启动代码编写有据可依。

### 5.4 启动流程
说明 BootROM、Boot 配置、向量获取、镜像校验（如有）、代码跳转、C 运行时初始化等过程，明确硬件与软件的交接边界。

### 5.5 多核启动时序
若为多核，应说明主核和从核的上电顺序、释放条件、同步机制、默认停机状态、启动入口配置方式，以及软件如何安全地 bring-up 多核。

### 5.6 启动软件要求
给出启动代码必须完成的事项清单，例如时钟/存储基础配置、栈初始化、BSS 清零、Data 拷贝、Trap/中断表初始化、保护机制设置、Cache 初始化等。

### 5.7 复位原因记录与清除机制
说明复位原因寄存器的记录方式、保持规则、清除方式、软件读取时机和多复位源叠加时的解释原则。

## 6. 中断系统

### 6.1 中断体系结构概述
从全局上说明中断在该内核中的处理框架：中断源如何进入内核、优先级如何比较、何时受理、进入后如何保存现场、如何返回。

### 6.2 中断源与路由机制
说明中断源来自哪些模块，是否经由集中式中断控制器/路由器进入内核，支持哪些路由方式、核绑定方式或目标核选择机制。

### 6.3 中断优先级模型
说明优先级编码方式、优先级数目、硬件比较规则、同优先级仲裁规则，以及优先级与抢占关系的定义。

### 6.4 中断受理条件
说明一个中断被 CPU 真正接收需要满足哪些条件，例如全局使能、源使能、优先级阈值、当前模式允许、中断已到达可见状态等。

### 6.5 中断屏蔽机制
说明屏蔽层次和粒度，包括全局中断屏蔽、优先级门限、本地源屏蔽、系统级屏蔽；并说明它们对 pending、active、wakeup 等状态的影响。

### 6.6 中断向量表
说明向量表格式、基地址、对齐要求、表项大小、表项内容、向量表重定位流程，以及软件初始化方法。

### 6.7 中断进入流程
按时序描述中断进入：当前指令完成规则、流水线冲刷、现场保存、向量获取、ISR 入口执行、状态位更新等。

### 6.8 中断返回流程
说明中断返回时硬件与软件的配合：恢复现场、清理 active 状态、处理尾链/延迟受理（如有）、返回到线程态或更低优先级 ISR 的规则。

### 6.9 中断嵌套行为
说明何时允许中断嵌套、嵌套的深度限制、优先级抢占关系、同级是否可重入、对栈和实时性的影响。

### 6.10 软件触发中断
若支持，应说明软件如何主动触发中断、使用场景（自检、核间通知、OS 调度等）、权限要求及调试限制。

### 6.11 快速中断 / 零延迟中断
若支持，应说明其与普通中断的差异，如独立现场、最小入口开销、不可被普通屏蔽影响等；还应说明使用限制。

### 6.12 中断延迟定义与测量方法
给出内核官方定义的中断延迟口径：从什么事件起点到什么软件可见点为止；说明测量方法、影响因素、推荐测试环境和结果解读方式。

### 6.13 中断编程指南
总结 ISR 编写建议，包括：保持短小、避免长临界区、避免不受控的可重入、谨慎访问共享资源、必要时使用屏障/volatile/锁。

### 6.14 中断相关寄存器
列出与中断行为直接相关的寄存器类别及用途，例如使能、挂起、优先级、向量基址、状态查询寄存器等，并说明这些寄存器与器件级中断控制器文档的边界。

## 7. 异常 / Trap 系统

### 7.1 异常体系结构概述
说明异常与中断的区别：异常通常由执行流错误或保护违规触发，中断通常来自外部事件；说明异常入口方式和总体处理框架。

### 7.2 异常分类
按照架构定义列出异常/Trap 类型，并给出每类异常的触发条件、优先级、同步/异步属性、可恢复性和典型软件场景。

### 7.3 同步异常与异步异常
说明两者的本质差异：同步异常通常可定位到具体指令，异步异常可能滞后呈现；并说明这对故障定位和软件恢复意味着什么。

### 7.4 异常优先级规则
说明多个异常同时存在时谁优先、异常与中断的相对优先级关系、异常嵌套是否允许以及升级逻辑。

### 7.5 Trap 向量表
说明异常入口表的组织方式、基地址、对齐要求、各类 Trap 的映射关系，以及初始化与重定位要求。

### 7.6 Trap 进入 / 返回流程
说明 Trap 发生后的硬件保存动作、Trap 信息记录、入口跳转、软件处理、可能的故障恢复以及合法返回方式。

### 7.7 Trap 信息寄存器
说明用于记录故障原因、故障地址、访问属性、故障主语句等上下文信息的寄存器，以及这些信息的读取窗口和清除规则。

### 7.8 故障升级规则
说明哪些故障可以局部处理后返回，哪些故障必须触发安全机制、复位或停机；说明升级链路和推荐的软件策略。

### 7.9 异常处理指南
给出 Trap Handler 的编写建议，包括日志记录、最小化副作用、恢复条件判定、不可恢复错误处理、与安全软件的接口建议。

### 7.10 典型故障场景
结合工程实际列举常见故障案例，例如非法地址访问、特权违规、非对齐、保护访问失败、错误异常返回、栈损坏等，并说明排查路径。

## 8. 存储模型与内核存储接口

### 8.1 内核视角下的地址空间
从 CPU 的角度定义地址如何被解释，哪些空间可取指、哪些空间可读写、哪些空间访问会触发异常，帮助软件建立统一的内存视图。

### 8.2 存储区域划分
说明各类存储区的功能属性、典型用途、访问延迟特征和是否支持共享/执行/保护，例如本地 RAM、共享 RAM、Flash、外设区、外部总线区等。

### 8.3 取指 / Load / Store 行为
说明代码取指、数据读取、数据写入在内核中的基本语义，尤其是写缓冲、重试、旁路、访存对齐和异常上报时机。

### 8.4 大小端模式
说明内核支持的大端/小端模式、固定还是可配置、对软件数据布局、网络协议栈和寄存器映射的影响。

### 8.5 对齐要求
说明不同宽度访问的对齐要求，不满足时的处理方式，是自动拆分还是报错；并说明对性能和异常的影响。

### 8.6 原子访问支持
说明是否支持原子读改写、独占访问、交换指令、位操作原子性等，以及这些机制对锁、信号量、OS 原语的支撑。

### 8.7 存储属性模型
说明地址空间是否具有缓存、缓冲、可执行、权限、共享性等属性；属性如何配置、由谁决定、软件如何正确使用。

### 8.8 推测执行 / 预取行为
说明内核是否存在预取、指令推测、数据推测或读提前行为，以及这些行为对外设寄存器、异常时序、调试观察和功能安全的影响。

### 8.9 存储访问顺序规则
说明 CPU 是否可能对访存重排序，何种场景需要软件主动约束顺序；特别是外设访问、DMA 共享区、核间通信共享变量等场景。

### 8.10 屏障指令与使用方法
说明指令同步屏障、数据同步屏障、数据内存屏障等机制（如支持），明确它们各自的适用场景、错误使用风险和推荐封装方式。

### 8.11 总线错误上报到内核的机制
