## 一、Agent 定义：四要素 + 两关键词

> 原文："An application that attempts to **achieve a goal** by **observing the world** and **acting upon it** using the **tools** that it has at its disposal."

| 要素 | 含义 |
|------|------|
| 🎯 目标驱动 | 不是"回答问题"，是"达成目标"，可能需多步 |
| 👀 感知环境 | 通过工具获取实时外部信息，不止靠训练数据 |
| 👐 采取行动 | 能改变外部状态（发邮件、改数据库），不止输出文本 |
| 🔧 工具在手 | 工具 = 能力边界；给什么工具决定能干什么 |

**两个关键词**：
- **Autonomous（自主）**：无需人类逐步指导
- **Proactive（主动）**：⭐ 没有显式指令也能推理"下一步该做什么"——Agent 与传统程序的分水岭：传统程序是**指令的奴隶**（没写 if 分支就傻掉），Agent 是**目标的奴隶**

**为什么强调 "an application" 而非 "a model"**：价值全在 Model+Tools+Orchestration 的**组装**，不在模型本身。裸调 LLM API 觉得"只是个聊天框"、用 Claude Code 能真干活——差别全在编排和工具。

## 二、认知架构三件套（全书骨架）

```
┌─────────────────────────────────────┐
│         Orchestration Layer         │  🎛️ 神经系统：循环 = 摄入信息 → 推理 → 决定下一步
│  ┌─────────┐      ┌───────────┐    │
│  │  Model  │ ───▶ │   Tools   │    │  🧠 大脑：LM，负责推理决策
│  │  (LM)   │ ◀─── │ (API等)   │    │  🙌 双手：连接外部世界
│  └─────────┘      └───────────┘    │
└─────────────────────────────────────┘
        循环直到达成目标或停止
```

- **Model**：一个或多个 LM，须能遵循 ReAct/CoT/ToT 推理框架；⚠️ 通常**不为**某个 Agent 配置专门训练——Agent 能力靠架构组装而非模型定制
- **Tools**：形态对齐 Web API（GET/POST/PATCH/DELETE），弥合内部能力与外部世界的鸿沟
- **Orchestration**：循环过程；复杂度弹性大（简单决策规则 ↔ 链式逻辑 + 概率推理）

## 三、核心矛盾：概率性大脑 vs 确定性世界 ⭐ 本讲精华

### 1. 先把"需要确定性"拆成三个不同需求

| 真实需求 | 含义 | 谁需要 |
|---------|------|--------|
| 结果可复现 | 同输入 → 同输出 | 测试回归 |
| 行为有界 | 绝不会做出格的事 | 功能安全 |
| 失效可知 | 错了能发现、能恢复 | 可靠性 |

LLM 三条全违反。但关键洞察：**这三条都不必对"大脑"提要求，可以对"系统"提要求。**

### 2. 核心论断

> 🎯 **矛盾不在组件层解决，在架构层解决。确定性是"系统属性"，不是"组件属性"。**

类比：没人指望 CAN 总线上某个晶体管绝对可靠——靠 CRC/重传/看门狗/ECC 在**系统层**获得可靠性。同理，没人能把 LLM"修"成确定性的，但可以用确定性机制把它**包起来**。

### 3. 确定性链条公式

```
模型的概率性意图 → [编排层的确定性闸门] → 工具的确定性执行 → 被操作系统的确定性状态变更
```

三个关键细节：
1. **工具执行确定 ≠ 调用决策确定**：模型若决定调 `delete_records("users")`，数据库会"非常确定地"删表。确定性执行器保证**忠实执行**，不保证**意图正确**——闸门必须装在执行**之前**
2. **编排层 = 确定性骨架 + 概率性心跳**：循环代码确定，每跳内容（想什么、调哪个工具）来自模型。编排层的价值 = 提供**挂载点**，拧上 validator / 权限检查 / HITL 闸门。确定性不是免费获得的，是**人为拧紧**的
3. **被操作系统是确定性底座**：数据库/API/事务系统——这是 Agent 架构坚持"所有状态变更走工具"的原因：可审计、可回滚、有边界

### 4. 经典模式：Propose & Dispose

**LLM 提议，确定性系统裁决。** 白皮书 p.21 已将 "human-in-the-loop review" 明确列为 Function Calling 场景——高风险动作不进实时链路，先人工审批。

> 💡 实例：Claude Code 本身就是这个结构——模型提议执行命令 → harness（确定性代码）检查权限 → 危险操作弹框等人类批准。**模型再"野"，出不了这个闸门。**

## 四、工程工具箱：6 层手段

| 层 | 手段 | 车规模拟 🚗 |
|---|------|-----------|
| 1. 收窄方差 | temperature→0、schema 约束解码（强制合法 JSON/枚举） | 信号限幅、量程检查 |
| 2. 输出校验 | 确定性 validator 检查每次输出，不合格即拒绝/重试 | 诊断机制 + D-COP |
| 3. 权限分级 | 只读工具自由用；写/不可逆动作走审批/HITL | ASIL 分解：QM 通道干活 + ASIL D 通道监督 |
| 4. 硬护栏 | 策略引擎硬编码红线，**不经过模型** | 硬件互锁/看门狗——软件再聪明也绕不过 |
| 5. 可恢复性 | 幂等 + 事务化设计，重试安全、失败可回滚 | 安全状态 / limp-home |
| 6. 统计验证 | 不证明"永不错"，证明"**错误率 < 目标**" | **PMHF！<10 FIT 本来就是概率性目标** |

## 五、车规视角：概率性并不新鲜 🚗

- **ISO 26262 Part 5 随机硬件失效就是概率性的**：不要求硬件"永不坏"，要求 PMHF 达标 + 诊断覆盖率够高。车规从不追求零失效，追求**失效率可量化、可检测、可控**
- LLM 的新挑战：**系统性失效也以概率形式表现**（同一 prompt 这次对下次错），26262 的"过程严控"方法失灵
- **ISO 21448 SOTIF** 正是这个家族的方法论：功能按设计工作、但设计能力有局限 → 统计验证 + 场景覆盖 + 接受准则
- **ISO/PAS 8800**（道路车辆 AI 安全）把这套思路延伸到 AI 组件

**方法论地图**：SOTIF 的统计验证思路 + 26262 的冗余/诊断/分解手段 ≈ Google 2025 续作的 Agent Ops（golden dataset ≈ 场景库，LM Judge ≈ 检测机制，trace ≈ 总线日志）。

## 六、金句集 💎

1. **确定性是系统属性，不是组件属性** —— 不靠把 LLM 修乖，靠架构把它包好
2. **智能归智能，红线归红线** —— 扭矩请求可以来自再智能的算法，safety monitor 只做边界检查，超界就 clamp
3. **LLM 提议，确定性系统裁决**（Propose & Dispose）
4. **安全带哲学**：不是让车祸不发生，是让车祸不致命
5. **人类本身就是概率性组件**——医生会误诊、司机会分心，社会靠 checklist/复核/分级授权把人包进可靠系统；Agent 需要同款"社会技术系统"，只是用代码实现

## 八、补充理解（2026-08-06 伴读讨论）

### 1. 概念考古：Agent 不是 2024 年发明的

| 时代 | 时间 | 代表 | "大脑" |
|------|------|------|--------|
| 学术奠基期 | 1986–2000s | Minsky《Society of Mind》(1986)、Wooldridge & Jennings 经典定义 (1995)、BDI 架构、MAS 研究 | 符号推理、手写规则 |
| 强化学习期 | 1998–2016+ | Sutton & Barto RL 体系、AlphaGo (2016) | 专用 RL policy |
| LLM 复活期 | 2022–至今 | ReAct 论文 (2022-10) → AutoGPT (2023-03) → 各家白皮书 (2024) → MCP/A2A | 通用语言模型 |

**血缘证据**：Wooldridge & Jennings (1995) 的定义 = autonomy + reactivity + **pro-activeness** + social ability——白皮书的 Autonomous/Proactive 两关键词**原封不动继承自 30 年前**。Russell & Norvig《AIMA》(1995) 更是整本书按 agent 组织："通过传感器感知环境、通过执行器作用于环境的实体"。

**为什么 2023–2024 爆发**：agent = 感知 + 决策 + 执行，三块拼图里感知（API）和执行（工具）早就成熟，**决策（通用推理能力）一直是瓶颈**。LLM 是第一个通用推理引擎，补上最后一块拼图，经典概念瞬间复活。🚗 类比线控转向：概念 1990 年代就有，要素不齐躺了三十年，要素齐备后才量产。

### 2. "acting upon it" 逐词拆解

- **语法**：`it` = the world；`act upon` 带明确作用对象 = **对世界本身施加动作**，与 observing 构成闭环
- **分水岭**：改变世界 ≠ 描述世界。Model 输出关于世界的文本（世界没变）；Agent 通过工具造成真实状态变更（世界变了）。判据：运行完之后世界上有没有某个比特因为它而不同
- **学术血缘**：observing ↔ sensors，acting upon ↔ actuators——白皮书是 Russell & Norvig 定义的逐词翻译；LLM Agent 的"执行器"就是工具调用
- **深层**：严格说**模型从不 act**——模型只生成 token，真实因果链是：模型文本 → 编排层放行 → 工具执行 → 数据库事务提交。文本通道与动作通道分离，才有地方装闸门/权限/审计（Propose & Dispose 的另一种表述）。🚗 类比：没有输出驱动级的 ECU——算得再快，PWM 悬空，没人叫它控制系统
