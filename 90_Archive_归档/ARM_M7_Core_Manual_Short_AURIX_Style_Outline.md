# 1. 文档说明

## 1.1 文档目的
本文用于说明基于 ARM Cortex-M7 的车规 MCU 内核在软件可见层面的主要行为，包括编程模型、异常体系、存储器体系、调试追踪、保护机制及启动复位相关约束。目标是为启动代码、OS、MCAL、驱动、编译器适配、测试与安全分析提供统一依据。

## 1.2 适用范围
本文适用于采用 **ARMv7E-M 架构的 Cortex-M7 内核**。文中所述内容分为两类：  
- **架构定义项**：寄存器模型、异常模型、Thumb-2 指令集、NVIC、SysTick、MPU、FPU、DWT/ITM/FPB 等。  
- **实现相关项**：具体中断数量、TCM/Cache 容量、片上 Flash/SRAM 布局、BootROM、复位树、调试口使能、安全岛/锁步/寄存器保护等。

## 1.3 目标读者
面向底层软件工程师、BSW/MCAL 工程师、OS 工程师、编译器与工具链工程师、验证工程师、功能安全工程师、应用工程师及调试工具工程师。

## 1.4 文档分层关系
本文建议与以下文档配合使用：  
- MCU 数据手册 / 目标规格书  
- SoC 总体手册  
- 存储器与地址映射手册  
- 中断控制器 / 中断路由手册  
- 系统控制与复位时钟手册  
- 调试追踪手册（CoreSight 集成说明）  
- BootROM / 安全启动手册  
- 功能安全手册  
- 编译器 ABI / CMSIS 适配说明  
- 勘误表 / 步进差异说明

## 1.5 名词、缩略语与术语
建议至少统一以下术语：Thread Mode、Handler Mode、Privileged、Unprivileged、Exception、Fault、NMI、VTOR、MSP、PSP、EXC_RETURN、NVIC、SCB、SysTick、MPU、FPU、TCM、Cache、DWT、ITM、FPB、ETM、WFI、WFE、Barrier。

## 1.6 文字与寄存器表示约定
统一十六进制、位域命名、寄存器复位值表示、保留位写 0 约束、地址格式、向量编号表示、优先级数值方向（数值越小优先级越高）等。

## 1.7 寄存器访问属性说明
Cortex-M7 内核寄存器通常采用 `RO / WO / RW / W1C / RAZ/WI` 等描述方式。除核心寄存器外，SCB/NVIC/MPU/FPU/调试寄存器可能带有特权限制、调试可见限制或实现相关保留位要求。

## 1.8 复位值与未定义行为说明
M7 的部分核心寄存器在架构上定义了复位后的初始行为，如 MSP/PC 由向量表装载；大量系统寄存器的默认值仍需以具体实现手册为准。对保留位、未实现位、非法组合、未对齐访问和无效异常返回等行为，应在产品手册中单列约束。

## 1.9 版本管理与修订记录
建议记录：内核版本、FPU/MPU/Cache/TCM 配置差异、调试模块裁剪情况、与上个步进的异常行为变化、勘误与已知限制。

# 2. 内核总览

## 2.1 设计目标
Cortex-M7 面向高实时性嵌入式控制场景，强调较低异常响应延迟、较高整数/DSP 运算效率、较好的 C 语言执行性能，以及较易软件生态集成。对于车规 MCU，常用来平衡实时控制、协议处理、诊断与一定程度的信号处理需求。

## 2.2 核心特性摘要
建议在正式手册中用表格汇总以下内容：  
- **架构**：ARMv7E-M  
- **位宽**：32 位  
- **指令集**：Thumb-2  
- **流水线**：典型六级流水线  
- **发射能力**：支持一定条件下的双发射，整体仍以顺序执行模型为主  
- **DSP 扩展**：支持饱和、MAC、SIMD 类打包运算  
- **浮点**：可选 FPU，车规 MCU 常见为单精度实现  
- **中断体系**：NVIC + SysTick  
- **保护**：Privileged/Unprivileged + MPU  
- **本地存储**：可选 ITCM / DTCM  
- **缓存**：可选 I-Cache / D-Cache  
- **调试追踪**：CoreSight 体系，常见含 DWT / ITM / FPB，ETM 视实现而定  
- **多核**：Cortex-M7 内核本身为单核，是否多核由 SoC 决定

## 2.3 架构框图
正式文档建议画出以下结构：  
- 取指与预取路径  
- I-Cache / ITCM 路径  
- 译码与发射  
- ALU / 乘加 / 移位 / DSP 路径  
- Load/Store 单元  
- D-Cache / DTCM / 系统总线路径  
- NVIC / SysTick / SCB  
- MPU / FPU  
- 调试与追踪单元  
- 外部 AXIM / AHB 接口

## 2.4 产品内核配置矩阵
建议按芯片型号给出：主频、是否带 ITCM/DTCM、Cache 大小、FPU 配置、外部中断数、ETM 是否实现、调试端口类型、是否多核、是否有安全扩展。

## 2.5 架构特性与实现特性边界
对 Cortex-M7 来说，下列内容通常是架构共性：  
- Thumb-2 编程模型  
- 异常编号和基本处理流程  
- Thread/Handler 模式  
- MSP/PSP、PRIMASK/BASEPRI/FAULTMASK  
- MPU / SysTick / NVIC / SCB 基本框架  
而以下内容通常是 SoC 实现特性：  
- Flash / SRAM / TCM 容量  
- 总线矩阵与仲裁  
- 中断输入个数  
- BootROM / BSL  
- 复位树与各类复位影响  
- 调试权限控制  
- 安全岛、锁步、ECC、BIST、寄存器保护控制器

## 2.6 与上一代 / 对标件差异摘要
若用于对比 Cortex-M4，可突出：更高性能流水线、可选 Cache、可选 TCM、更强分支预测和更高吞吐。  
若对比 AURIX/TriCore，应明确：M7 采用 **Fault/Exception + NVIC** 模型，而非 TriCore 式 Trap/CSA/ENDINIT 模型；M7 的软件生态更偏 CMSIS/RTOS 风格，而非 TriCore 专有寄存器与上下文管理机制。

# 3. 编程模型

## 3.1 处理器状态模型
M7 以 **Thread Mode** 和 **Handler Mode** 为基本运行状态，以 **Privileged** 和 **Unprivileged** 为权限维度。异常进入后自动切换到 Handler Mode，通常以特权态执行。

### 3.1.1 用户态 / 监督态 / 管理态
M7 没有 TriCore 那种多级监督/I/O 特权分层，通常仅区分：  
- **Privileged**：可访问全部系统控制寄存器、配置中断屏蔽、MPU 等  
- **Unprivileged**：受限访问，不能直接改写关键系统控制寄存器  
此外还区分 Thread Mode 与 Handler Mode，后者用于异常处理。

### 3.1.2 I/O 特权等级
Cortex-M7 架构本身 **不定义独立 I/O 特权等级模型**。外设访问是否受限，通常通过 MPU、总线防火墙或 SoC 安全控制器实现。

### 3.1.3 调试状态
支持 halt、single-step、断点、观察点、调试事件进入等机制。调试状态对流水线、异常响应、低功耗进入与寄存器可见性会产生影响，具体行为与 CoreSight 集成方式相关。

## 3.2 通用寄存器模型
M7 采用典型 ARM M-profile 寄存器模型：`R0-R12`、`SP`、`LR`、`PC`、`xPSR`。

### 3.2.1 地址寄存器组
M7 不区分专门的地址寄存器组和数据寄存器组，通用寄存器可承担地址与数据用途。地址计算、栈操作、数组访问一般通过通用寄存器完成。

### 3.2.2 数据寄存器组
同样由 `R0-R12` 承担整数、逻辑、位操作和参数传递职责。ABI 中 `R0-R3` 常用于参数与返回值，`R4-R11` 多为被调用者保存寄存器。

### 3.2.3 特殊用途寄存器
主要包括：  
- `MSP` / `PSP`：主栈 / 进程栈  
- `LR`：异常返回时还承载 `EXC_RETURN` 编码  
- `PC`：程序计数器  
- `xPSR`：程序状态  
- `CONTROL`、`PRIMASK`、`BASEPRI`、`FAULTMASK`：控制与屏蔽  
- `SCB` / `NVIC` / `SysTick` / `MPU` / `FPU` 相关寄存器

## 3.3 程序状态字 / 状态标志
M7 使用 `xPSR` 统一呈现程序状态，其中常用标志位包括 `N/Z/C/V/Q`，中断号信息由 `IPSR` 提供，执行状态与 Thumb 状态由 `EPSR` 相关位体现。

## 3.4 系统寄存器模型
建议按以下分组说明：  
- **核心控制类**：CONTROL、PRIMASK、BASEPRI、FAULTMASK  
- **异常控制类**：SCB 中的 ICSR、AIRCR、SCR、CCR、SHCSR 等  
- **Fault 状态类**：CFSR、HFSR、DFSR、MMFAR、BFAR、AFSR  
- **中断类**：NVIC 使能、挂起、优先级、STIR  
- **时基类**：SysTick  
- **保护类**：MPU  
- **浮点类**：FPU 寄存器  
- **调试与性能监控类**：DWT、ITM、FPB、可选 ETM

## 3.5 上下文模型
M7 的上下文切换以“软件 + 异常硬件自动压栈”混合方式实现，没有 TriCore 的 CSA 链表模型。

### 3.5.1 上下文类型
可区分为：  
- 普通函数调用上下文  
- 异常自动保存基本上下文  
- FPU 扩展上下文  
- RTOS 任务切换上下文

### 3.5.2 上下文保存区 / 上下文链表
M7 **无硬件 CSA 链表机制**。上下文主要保存在当前活动栈中，由 MSP 或 PSP 承担。

### 3.5.3 函数调用上下文
遵循 AAPCS / EABI 约定。函数调用主要依赖栈与通用寄存器，深度递归会直接消耗栈空间，因此栈深评估非常关键。

### 3.5.4 中断 / Trap 上下文
异常进入时，硬件自动压入基础堆栈帧：`R0-R3, R12, LR, PC, xPSR`；如启用 FPU，则可能发生浮点上下文自动或延迟压栈。软件异常处理框架还需根据需求扩展保存 `R4-R11` 等寄存器。

## 3.6 数据类型与数据格式
原生支持 8/16/32 位整数访问，支持 64 位数据运算的组合处理，支持定点 DSP 类数据与可选浮点运算。正式手册应说明整数、浮点、打包 SIMD 数据和地址类型的使用边界。

## 3.7 对齐与字节序
M7 通常按 **小端** 使用。未对齐访问的支持能力受指令类型和系统配置影响，某些场景可透明支持，某些场景可能导致 Fault 或性能下降，因此正式手册应列清楚“允许 / 禁止 / 可配置”的边界。

## 3.8 地址模型
M7 采用 4GB 线性地址空间，没有 MMU 式虚实地址翻译。是否为 Code、SRAM、Peripheral、External Memory，主要由系统存储映射和 MPU 属性共同决定。

## 3.9 ABI / 编译器接口约束
建议明确：  
- `-mcpu=cortex-m7 -mthumb` 为基本编译约束  
- 若启用 FPU，应同步约束 `-mfpu` 与 `-mfloat-abi`  
- 栈 8 字节对齐要求  
- 异常帧布局  
- CMSIS 头文件与系统启动文件约定  
- RTOS 上下文切换保存集

# 4. 指令系统总览

## 4.1 指令集概述
Cortex-M7 使用 **Thumb-2 指令集**，指令长度为 16 位或 32 位混合编码。其目标是兼顾代码密度与执行性能。

## 4.2 指令编码格式
正式手册可不重写 ARM ISA 全文，但应说明：M7 为 Thumb 状态执行核，既有 16 位短指令，也有 32 位扩展指令；与异常返回、分支范围、立即数编码、访存方式密切相关的编码特性建议单列。

## 4.3 指令语法与伪代码约定
建议采用统一模板描述：  
- 指令语法  
- 操作数  
- 功能说明  
- 标志位影响  
- 异常条件  
- 是否受对齐、权限、MPU 属性限制  
- 性能提示（如是否受 Flash wait state、Cache/TCM 命中影响）

## 4.4 指令分类目录

### 4.4.1 数据传送指令
包括 MOV、LDR/STR、LDM/STM、PUSH/POP、符号扩展/零扩展、位域提取与插入等。

### 4.4.2 整数运算指令
包括加减乘除、比较、饱和、绝对值、前导零计数等，适合一般控制与定点运算。

### 4.4.3 逻辑与位操作指令
包括 AND/ORR/EOR/BIC、移位、旋转、位清零、位测试、位域操作等。

### 4.4.4 分支与流程控制指令
包括 B、BL、BX、CBZ/CBNZ、IT（旧式条件执行语义相关）、SVC、异常返回相关流程。

### 4.4.5 Load/Store 与存储器访问指令
包括普通访存、多寄存器搬运、独占访问、栈访问、字节/半字/字/双字相关操作。

### 4.4.6 系统控制指令
包括 MRS/MSR、CPS、WFI、WFE、SEV、ISB、DSB、DMB 等。

### 4.4.7 DSP / SIMD / CRC / 专用扩展指令
M7 支持 ARMv7E-M DSP 扩展，包括部分打包加减、饱和、乘累加等。**CRC 专用指令并非 M7 架构标准项**，若产品实现有额外扩展，应在扩展手册中说明。

### 4.4.8 浮点指令
若实现带 FPU，则支持对应的浮点运算、转换、比较、访存与状态控制指令。具体是单精度还是更高配置，以实现手册为准。

## 4.5 特权指令与受限指令
涉及中断屏蔽、系统控制、MPU/FPU 配置、异常控制、Cache/TCM 管理、某些调试控制的操作通常要求特权态执行。

## 4.6 原子与同步指令
M7 通过 `LDREX / STREX / CLREX` 和 `DMB / DSB / ISB` 实现并发同步、临界区和存储可见性控制。多核 SoC 或 DMA 场景下这些指令尤其关键。

## 4.7 未实现 / 保留 / 非法指令行为
对未定义指令、未启用协处理器/FPU 指令、状态非法指令组合等，通常会触发 UsageFault 或相关 Fault。正式手册应列出易误用场景。

## 4.8 指令时序与性能说明
M7 的性能受流水线、双发射条件、分支预测、Cache/TCM 命中、总线仲裁、Flash wait state 影响显著。正式手册更适合给出“影响因子说明”，而不是单条指令静态周期表。

# 5. 微架构与执行引擎

## 5.1 流水线总体结构
Cortex-M7 通常描述为 **六级流水线** 的高性能 M-profile 内核。它相较 M3/M4 更重视取指效率、分支处理和访存性能。

## 5.2 发射与并行能力
M7 支持一定条件下的双发射，但并非所有指令组合都可并行。实际性能高度依赖代码排列、相关性、访存冲突和编译器调度。

## 5.3 取指与预取机制
支持高效取指、预取与指令缓冲；若实现带 I-Cache 或 ITCM，代码放置位置对执行效率影响很大。

## 5.4 分支处理机制
M7 相比低端 M-profile 内核具有更积极的分支处理能力。分支密集代码的性能与预测命中、指令布局和目标地址局部性有关。

## 5.5 数据通路与旁路
整数、DSP、访存、浮点（若有）等路径之间存在相关性约束。对车规实时应用，建议关注“连续访存 + 分支 + 外设访问”组合下的最坏时延。

## 5.6 Load/Store 子系统
访存既可走 TCM，也可走 Cache/系统总线。对外设区访问通常表现为 Device 类型，不应按普通缓存内存对待。

## 5.7 存储访问次序与内存可见性
M7 遵循 ARM 的存储模型。对中断、DMA、共享内存和多主设备场景，应正确使用屏障指令保证顺序与可见性。

## 5.8 缓存与本地存储访问路径
典型访问优先级可概括为：  
- **ITCM/DTCM**：低延迟、确定性好  
- **Cache 命中**：性能较高但需考虑维护  
- **系统总线 / Flash / 外部存储器**：延迟更依赖实现

## 5.9 确定性与实时性说明
若应用强调中断确定性、控制闭环抖动与最坏执行时间，建议将关键代码与数据放入 TCM，降低 Cache 未命中、Flash 等待和总线争用的影响。

## 5.10 性能监控与事件计数器
M7 常通过 **DWT** 提供周期计数、访存与事件统计能力。正式手册应说明各事件计数器是否实现、是否可在量产态使用、调试态与运行态是否一致。

# 6. 存储器体系与地址空间

## 6.1 地址空间总览
M7 面向 4GB 统一线性地址空间。不同地址段的用途由 SoC 定义，但核心通常可区分代码区、SRAM 区、外设区和外部存储区。

## 6.2 地址翻译机制
M7 **无 MMU**，一般不存在页表级虚实地址翻译。保护与属性控制主要依赖 MPU，而非地址重映射机制本身。

## 6.3 本地程序存储器
若实现带 **ITCM**，它适合放置中断入口、控制核心环路、性能敏感代码和频繁调用函数。ITCM 容量与装载方式属于 SoC 实现相关项。

## 6.4 本地数据存储器
若实现带 **DTCM**，适合放置栈、控制关键变量、中断共享小数据、DMA 不参与的一致性敏感数据。正式手册应说明 DTCM 是否支持 DMA 可达、ECC/奇偶校验、启动初始化策略。

## 6.5 共享存储器
片上 SRAM、外部 RAM 或多核共享 RAM 不属于 M7 架构必选项，但对 M7-based SoC 很关键。正式手册应说明共享区的缓存策略、DMA 协同方式和核间同步要求。

## 6.6 本地 Flash / 程序 Flash
Flash 不是 M7 架构本身定义的存储体，而是 SoC 常见实现。正式手册需说明 Flash wait state、预取、I-Cache 命中、擦写对执行的影响，以及是否支持 XIP。

## 6.7 缓存体系
M7 可选独立 I-Cache / D-Cache。启用 Cache 后，应特别说明：  
- Cache line 大小  
- 失效 / 清除 / 清回写接口  
- DMA 一致性处理  
- 自修改代码限制  
- 启动阶段启用顺序

## 6.8 访问属性控制
主要依赖 MPU 设置内存类型、缓存策略、执行权限和访问权限。对外设寄存器区必须使用合适属性，避免错误缓存或乱序副作用。

## 6.9 原子访问与互斥资源
对于共享变量、锁、环形队列、核间标志位等，建议使用独占访问指令配合屏障。是否还能借助总线信号量/硬件互斥器，属于 SoC 层增强能力。

## 6.10 存储器错误处理
常见错误路径包括：  
- MPU 保护违规 → MemManage Fault  
- 总线从设备错误 / 异常响应 → BusFault  
- 非法执行区取指 → MemManage / HardFault（依配置）  
- 栈溢出一般需软件或 MPU 辅助检测

## 6.11 Overlay / 标定支持
**Overlay 并非 Cortex-M7 内核标准能力。** 若项目需要在线标定/地址重映射，通常由 SoC 总线矩阵、Flash 控制器、调试逻辑或 MPU/系统映射器实现，应放在平台手册中描述。

# 7. 中断系统

## 7.1 中断体系总览
M7 使用 **NVIC** 管理内核异常和外部中断，支持优先级、嵌套、抢占、挂起、激活与软件触发等机制。

## 7.2 中断请求输入接口
外部中断输入数量由实现决定，M7 架构上可支持较多中断源。具体每个中断源如何来自外设、路由器或聚合器，由 SoC 设计决定。

## 7.3 中断优先级模型
优先级数值越小，优先级通常越高。优先级可进一步划分为抢占优先级与响应排序字段，分组方式由 `AIRCR.PRIGROUP` 控制。

## 7.4 中断向量表
向量表包含初始 MSP、复位入口以及各异常/中断入口地址。向量表可放在 Flash、SRAM 或其他可执行存储区。

### 7.4.1 中断向量表基址寄存器
通过 `VTOR` 配置向量表基址。若系统支持 RAM 向量表或 Boot 后重定位，应明确初始化时序。

### 7.4.2 向量间距配置
M7 采用固定向量表条目布局，不像某些架构支持可编程向量间距。

### 7.4.3 向量表对齐约束
向量表需满足架构要求的对齐限制，实际对齐大小与表规模和实现配置相关。正式手册应给出工程可直接使用的对齐约束。

## 7.5 中断响应流程
典型流程为：识别最高优先级挂起异常 → 自动压栈 → 更新活动异常号 → 跳转 ISR。返回时依据 `EXC_RETURN` 恢复现场。

## 7.6 中断嵌套与抢占
支持嵌套与抢占，硬件自动完成基本上下文入栈，结合 tail-chaining 和 late arrival 可降低异常切换开销。

## 7.7 中断屏蔽机制
常见屏蔽手段包括：  
- `PRIMASK`：屏蔽大多数可屏蔽异常  
- `BASEPRI`：设置优先级阈值  
- `FAULTMASK`：屏蔽除 NMI 外的大多数异常  
不同机制适合不同实时性与安全性场景。

## 7.8 软件触发中断
可通过 NVIC 相关机制软件置挂起；若实现支持 STIR，也可用于软件触发某些外部中断号。

## 7.9 中断与调试的交互
单步、断点、halt、向量捕获、调试异常可能影响中断时序与挂起状态。正式手册应明确调试态是否允许中断继续运行。

## 7.10 中断设计建议
建议：  
- 高实时 ISR 尽量短小  
- 中断入口避免访问高等待态 Flash  
- 关键 ISR 放入 ITCM  
- 用 `BASEPRI` 管理 RTOS 临界区  
- 共享数据配合屏障和原子访问

# 8. Trap / 异常 / 错误体系

## 8.1 异常体系总览
对 M7，更准确的术语是 **Exception / Fault**，而不是 TriCore 风格 Trap。异常体系统一由向量表和 NVIC/SCB 协同管理。

## 8.2 Trap 分类
可映射为以下异常类别：  
- Reset  
- NMI  
- HardFault  
- MemManage  
- BusFault  
- UsageFault  
- SVCall  
- DebugMonitor  
- PendSV  
- SysTick  
- 外部 IRQ  
正式手册建议直接用 ARM 命名，不再沿用 Trap Class 术语。

## 8.3 同步异常与异步异常
非法指令、特权违规、除零配置检查、无效状态等多为同步 Fault；总线错误可能表现为同步或异步，需结合寄存器与具体访问路径判断。

## 8.4 NMI 机制
NMI 具有极高优先级，仅次于 Reset。适合接入不可屏蔽的严重错误、外部安全事件或关键系统监控信号。

## 8.5 Trap 向量表
M7 不单独区分 Trap 向量表与中断向量表，全部异常均位于统一向量表中。

## 8.6 Trap 现场保存与返回
异常进入自动压入基本堆栈帧；返回时由 `BX LR` 携带的 `EXC_RETURN` 编码决定恢复路径、使用 MSP/PSP 以及是否返回线程态。

## 8.7 异常信息寄存器
正式手册建议重点介绍：  
- `CFSR`  
- `HFSR`  
- `MMFAR`  
- `BFAR`  
- `DFSR`  
- `AFSR`  
- `ICSR`  
并明确其清除方式、保留位和调试诊断顺序。

## 8.8 常见 Trap 逐项说明

### 8.8.1 非法指令 / 未实现指令
通常归入 UsageFault。启用未实现扩展、错误跳转到非 Thumb 状态或执行非法编码，都可能触发。

### 8.8.2 特权违规
非特权态访问特权资源，或对受限系统寄存器执行写操作，可能触发 Fault 或被硬件忽略，需按寄存器规则分别说明。

### 8.8.3 存储保护异常
MPU 拒绝访问、禁止执行区取指、不可访问区域读写，通常进入 MemManage Fault。

### 8.8.4 数据对齐异常
某些未对齐访问会被硬件支持，某些则可能触发 UsageFault 或 BusFault，需按访问类型和配置项说明。

### 8.8.5 同步数据错误 / 异步数据错误
总线从设备错误、返回错误响应、外部存储器异常、ECC 错误上报等，多通过 BusFault/HardFault 表现。

### 8.8.6 程序完整性错误 / 数据完整性错误
M7 架构本身不定义代码签名校验或完整性控制器；这类机制通常由 Flash 控制器、ECC、BootROM 或安全模块实现，并通过 Fault/NMI/Reset 上报。

### 8.8.7 上下文链耗尽 / 下溢
**M7 无 CSA 上下文链机制，此项不适用。** 对 M7 更关键的是普通栈溢出、双栈配置错误和异常返回帧损坏。

### 8.8.8 系统调用
通过 `SVC` 触发，常用于 RTOS 系统调用、特权切换入口或安全监控接口。

## 8.9 异常处理软件框架建议
建议建立统一 Fault 框架：  
- 读取堆栈帧  
- 读取 SCB Fault 状态寄存器  
- 解码异常来源  
- 判断是否可恢复  
- 必要时记录到 NVM / RAM 日志  
- 对严重故障进入安全状态或触发系统复位

# 9. 保护与隔离机制

## 9.1 保护架构总览
M7 的核心保护机制主要是：  
- Thread/Handler 模式分离  
- Privileged/Unprivileged 权限分离  
- MPU 区域访问控制  
- Fault 上报与隔离  
更多系统级隔离通常依赖 SoC 防火墙、总线保护器和安全控制器。

## 9.2 特权保护
关键系统寄存器配置、中断屏蔽、MPU/FPU 管理等应限制在特权态执行。正式手册建议给出“仅特权可写寄存器清单”。

## 9.3 I/O 权限保护
M7 内核自身不单独定义 I/O 特权级。若需区分普通外设与安全外设，应通过 MPU + SoC 保护单元实现。

## 9.4 代码保护
可利用 MPU 对代码区设置只读、可执行或不可执行属性，并将 SRAM/外设区配置为 XN，以减少误跳转执行风险。

## 9.5 数据保护
可通过 MPU 将关键数据区限制为特权读写、只读或不可访问，支持栈保护、任务隔离和关键参数只读化。

## 9.6 保护集 / 任务保护上下文
M7 没有 TriCore 那种硬件保护集切换机制。若需要多任务隔离，通常由 RTOS 在任务切换时重装 MPU 区域配置。

## 9.7 外设与寄存器访问保护
主要属于 SoC 集成层问题。建议在平台手册中说明哪些外设寄存器受总线安全控制、主设备 ID、调试访问授权或生命周期状态限制。

## 9.8 ENDINIT / Safety ENDINIT 机制
**M7 架构不定义 ENDINIT / Safety ENDINIT。** 若产品想引入类似“关键寄存器写保护窗口”，应作为 SoC 自定义机制单列说明。

## 9.9 本地存储器安全保护
对 TCM、片上 SRAM、共享 RAM，可通过 MPU 属性、ECC/奇偶校验、启动初始化和访问主设备约束进行安全保护。ECC 属 SoC 侧能力。

## 9.10 调试访问保护
调试口开放、量产锁定、认证解锁、生命周期控制等一般不属于 M7 核心架构，而是 SoC 安全设计的一部分。

## 9.11 保护异常与告警路径
M7 架构层主要通过 MemManage/BusFault/HardFault/NMI 报告保护失效。若产品还集成安全管理单元，可将 Fault 再上送系统安全路径。

## 9.12 软件配置建议
建议：  
- 默认启用 MPU 基础隔离  
- SRAM/外设区默认 XN  
- 关键栈单独 MPU 保护  
- 非特权任务限制系统寄存器访问  
- Fault handler 明确区分可恢复与不可恢复场景

# 10. 启动、Boot、复位与停机

## 10.1 启动与复位总体说明
对 M7 而言，最核心的架构定义启动行为是：**复位后从向量表取初始 MSP 和 Reset Handler 地址并开始执行。** 其他 Boot 流程大多属于 SoC 设计。

## 10.2 复位分类
Cortex-M7 架构本身不完整定义车规 MCU 所需的全部复位树。产品层通常需要定义：POR、外部复位、看门狗复位、软件系统复位、锁死触发复位、调试复位、局部模块复位等。

## 10.3 各类复位影响矩阵
正式手册建议明确：  
- 核心寄存器是否重置  
- NVIC/SCB/MPU/FPU 状态是否清零  
- Cache/TCM/ECC 状态是否重建  
- SRAM/TCM/备份域是否保持  
- 外设与调试状态是否保持

## 10.4 Boot 模式选择
**Boot mode 选择不是 M7 架构定义项。** 该部分应由 BootROM / 启动引脚 / OTP / 生命周期状态 / 安全启动策略共同定义。

## 10.5 BootROM / SSW / 固件流程
M7 架构只关心最终跳转到 Reset Handler。BootROM、镜像选择、签名校验、镜像回滚、升级恢复等逻辑均属 SoC 启动固件范畴。

## 10.6 次核启动流程
若产品为多核 M7 SoC，此项应说明次核上电、保持、释放、入口地址设置与核间同步。**单个 M7 内核架构本身不包含次核概念。**

## 10.7 无有效启动头时的处理
非 M7 架构定义项。产品可选择进入 BootROM、BSL、故障安全态或等待调试下载。

## 10.8 Bootstrap Loader
ASC/CAN/UART/USB/CAN FD/Ethernet BSL 等均为 SoC/固件层能力，不属于 M7 内核定义。

## 10.9 软件复位与停机请求
M7 可通过 `AIRCR.SYSRESETREQ` 触发系统复位请求；WFI/WFE 用于等待中断/事件，并不等同于完整停机模式。更深停机策略由系统电源管理实现。

## 10.10 Boot 与安全机制交互
安全启动、签名认证、调试口锁定、启动测量、启动自检等多为 BootROM 与系统安全控制器完成，内核主要承担异常/Fault 侧的软件入口。

## 10.11 调试模式下的启动差异
调试器可在复位后接管、向量捕获、修改 PC/MSP 或阻止用户代码立即运行。正式手册应单列“调试复位启动路径”。

# 11. 多核子系统

## 11.1 多核拓扑结构
Cortex-M7 是单核 IP。若 MCU 集成多个 M7 或与其他核异构组合，则多核拓扑属于 SoC 描述内容。

## 11.2 核间启动与生命周期管理
建议在 SoC 手册中说明核保持、释放、复位、唤醒和停止机制。M7 架构层通常仅提供 SEV/WFE 等轻量同步原语。

## 11.3 核间通信机制
常见方式包括共享 RAM、邮箱、中断、事件、队列、信号量、硬件互斥器。M7 本身不定义邮箱 IP。

## 11.4 核间同步机制
可依赖 `SEV/WFE`、独占访问、屏障和共享内存协同实现。实际效果受缓存一致性与总线设计影响。

## 11.5 共享资源仲裁
TCM 通常是核本地资源；共享 SRAM、外设和外部存储器的仲裁则由总线矩阵完成。

## 11.6 多核中断路由
是否支持中断定向到特定核、广播到多核或由路由器分发，完全取决于 SoC 中断控制体系。

## 11.7 多核调试与追踪
多核系统需补充说明：同步 halt、交叉触发、核间 trace 对齐、共享时间戳和多核性能观测方案。

## 11.8 多核隔离与 Freedom from Interference
建议从以下维度描述：  
- TCM / 本地栈分离  
- MPU 任务隔离  
- 共享 RAM 分区  
- DMA 主设备隔离  
- 总线带宽争用分析  
- 中断与调试互扰分析

---

# 12. 调试、追踪与标定

## 12.1 调试架构总览
M7 通常集成于 Arm CoreSight 体系中，支持 run-control、断点、观察点、性能计数和软件 trace。

## 12.2 外部调试接口
常见为 **SWD**，也可能支持 **JTAG**。具体引脚复用、调试带宽和电气要求由 SoC 规格书定义。

## 12.3 Run-Control
支持 halt、resume、single-step、寄存器读写、内存访问和向量捕获等基本能力。

## 12.4 断点与观察点
- **FPB**：硬件断点 / 代码补丁  
- **DWT**：数据观察点、事件统计  
正式手册应写明资源个数是否被裁剪。

## 12.5 触发与交叉触发
若实现集成 CTI/CTM 或系统级调试触发网络，应说明 CPU、Trace、外设、比较器之间的联动关系。若未实现，应明确不支持。

## 12.6 Trace 体系
建议按以下层次说明：  
- ITM：软件事件输出  
- DWT：事件与计数  
- ETM：指令 trace（可选）  
- TPIU / ETB / ETF：trace 输出或缓存（实现相关）  
车规场景下还应说明量产态是否保留部分 trace 功能。

## 12.7 性能分析支持
利用 DWT CYCCNT、PC 采样、ETM、软件时间戳可做 ISR 抖动、函数耗时、cache 效应和总线阻塞分析。

## 12.8 Overlay / 在线标定支持
**非 M7 内核标准项。** 若项目面向标定应用，应由 SoC 映射/调试逻辑提供支持，不能归因于 M7 核心本身。

## 12.9 调试安全
调试锁定、认证解锁、生命周期状态控制、生产模式屏蔽等均为 SoC 层机制。建议单列与安全启动的一致性要求。

## 12.10 调试器使用建议
建议明确：  
- 复位连接模式  
- Flash 下载时 cache/MPU 处理  
- Fault 调试建议  
- 多核停核策略  
- 量产环境调试权限边界

# 13. 功耗、时钟与运行模式（内核视角）

## 13.1 时钟体系对内核的影响
内核频率直接影响执行吞吐，但实际性能还受 Flash wait state、TCM/Cache 命中和总线频率耦合影响。

## 13.2 运行模式
从内核视角，常见运行状态包括正常运行、调试 halt、WFI/WFE 等等待状态。更深层低功耗模式通常由系统电源控制器决定。

## 13.3 低功耗进入条件
通常依赖 `WFI` 或 `WFE`，并结合系统控制寄存器和平台电源管理策略进入 Sleep / DeepSleep 类模式。

## 13.4 唤醒源
中断、事件、复位、调试活动、某些安全告警均可能成为唤醒源，具体取决于平台实现。

## 13.5 低功耗模式下的寄存器保持性
核心寄存器、NVIC 状态、TCM/SRAM/Cache/FPU 状态是否保持，必须由 SoC 手册明确，M7 架构不统一规定全部模式的保持矩阵。

## 13.6 低功耗与安全机制
低功耗模式下需重新评估：  
- 中断可达性  
- 监控时钟是否仍有效  
- 看门狗是否继续计数  
- 调试是否禁止  
- 醒来后 cache/TCM/MPU 是否需要重建

---

# 14. 安全机制与诊断（内核相关）

## 14.1 内核安全目标概述
M7 内核层更适合作为系统安全架构中的“可控执行主体”，依靠权限、MPU、Fault、调试诊断和可预测中断响应支撑上层安全机制。

## 14.2 故障模型
建议至少覆盖：  
- 非法执行流  
- 指令/数据访问越界  
- 堆栈破坏  
- 中断异常嵌套错误  
- 共享数据并发错误  
- FPU 上下文丢失  
- Flash 等待态引发的时序劣化

## 14.3 错误检测机制
核心相关检测机制主要包括：  
- MemManage / BusFault / UsageFault / HardFault  
- NMI  
- 锁死（Lockup）指示  
- MPU 检查  
- 调试与 trace 辅助观测  
ECC/奇偶、BIST、时钟监控通常属于 SoC 安全机制。

## 14.4 自检机制
M7 架构本身不强制提供 LBIST/MBIST。软件层可做上电寄存器测试、栈测试、MPU 测试、异常路径测试、FPU/DSP 指令测试；更底层 BIST 由 SoC 提供。

## 14.5 锁步机制（如有）
**锁步不是 Cortex-M7 标准架构功能。** 若产品采用双核锁步或比较器机制，应单独在安全手册/CPU 子系统手册说明。

## 14.6 安全告警接口
M7 自身更偏通过异常/Fault/NMI 输出错误状态；若系统有 SMU/ESM/错误管理器，可将内核 Fault 进一步映射到安全告警域。

## 14.7 故障处理策略
建议分级处理：  
- 可恢复：记录、隔离、任务重启  
- 有风险但可受控：进入降级模式  
- 不可恢复：安全状态 + 系统复位

## 14.8 软件 Assumptions of Use
建议明确：  
- 启动阶段正确设置 VTOR、栈和 MPU  
- 中断优先级分组统一  
- DMA/共享内存与 cache 维护正确  
- Fault handler 不可为空实现  
- FPU 使用时 RTOS 必须正确保存上下文

## 14.9 安全使用建议
对于车规项目，建议：  
- 关键控制任务代码放 ITCM  
- 关键数据放 DTCM 或受保护 RAM  
- 默认开启 MPU 基础隔离  
- 建立统一 Fault 注入与恢复测试  
- 对所有异常路径给出可验证的软件策略

# 16. 软件开发与移植指南

## 16.1 启动代码要求
必须完成：初始化栈、设置向量表、可选初始化 TCM、配置 Cache/MPU/FPU、清零 BSS、搬运数据段、最后进入主程序。

## 16.2 链接脚本要求
应明确代码、只读数据、读写数据、栈、堆、中断向量表、ITCM/DTCM、共享 RAM 的布置策略。

## 16.3 编译器注意事项
建议明确：  
- `-mcpu=cortex-m7 -mthumb`  
- FPU/ABI 选项一致  
- `-ffunction-sections/-fdata-sections` 是否使用  
- 优化等级对时延与调试性的影响  
- 是否启用 `unaligned access`

## 16.4 OS 适配建议
RTOS 需要正确处理：  
- PendSV / SysTick  
- BASEPRI 临界区  
- MSP/PSP 分工  
- FPU 上下文  
- 中断优先级分组  
- 栈对齐约束

## 16.5 多核软件建议
若产品为多核 SoC，应补充核间启动、共享缓存维护、共享 RAM 协议和核间中断约束。单核 M7 可不展开。

## 16.6 Trap / Fault 软件框架建议
建议提供统一 Fault 框架与解码库，支持提取堆栈帧、寄存器快照、异常号、故障地址和恢复路径判定。

## 16.7 驱动开发注意事项
外设驱动要明确外设区内存属性、寄存器访问顺序、必要的 `volatile` 语义、屏障需求以及 DMA 与 cache 一致性处理。

## 16.8 性能调优建议
关键建议：  
- 热代码放 ITCM  
- 热数据放 DTCM  
- 合理使用 I/D Cache  
- 减少高等待态 Flash 随机访问  
- 优化中断栈与优先级  
- 用 DWT 做实测而非仅靠静态估计

# 17. 验证、测试与可测性建议

## 17.1 架构一致性验证点
包括寄存器复位行为、特权切换、异常进入返回、基本指令正确性、FPU/DSP 路径、MPU 权限生效等。

## 17.2 启动与复位验证点
验证向量表装载、MSP/PC 初始化、SYSRESETREQ 行为、调试复位连接、不同复位源保持矩阵。

## 17.3 中断 / Trap 验证点
验证优先级抢占、tail-chaining、late arrival、PRIMASK/BASEPRI/FAULTMASK 行为、异常返回路径、SVC/PendSV/SysTick 协同。

## 17.4 保护机制验证点
验证 MPU 区域权限、XN、生效时序、任务切换重装、非法访问 Fault、栈保护策略。

## 17.5 调试与追踪验证点
验证断点、观察点、CYCCNT、ITM 输出、可选 ETM trace、调试锁定与量产模式差异。

## 17.6 安全机制验证点
验证 Fault handler 健壮性、锁死处理、关键异常上报、启动自检、容错恢复与安全状态转换。

## 17.7 量产可测性说明
应明确哪些调试特性量产关闭，哪些仍用于故障分析；如保留现场故障记录机制，其访问路径与安全约束要一并说明。

# 18. 典型时序与用例

## 18.1 上电到用户代码运行时序
建议画出：复位释放 → BootROM（若有）→ 向量表装载 MSP/PC → Reset Handler → 系统初始化 → `main()`。

## 18.2 中断响应时序
建议画出：中断挂起 → 优先级比较 → 自动压栈 → ISR 入口 → 中断嵌套/尾链接 → 异常返回。

## 18.3 Trap 进入与返回时序
建议改名为“Fault/Exception 进入与返回时序”，重点展示堆栈帧、`EXC_RETURN`、MSP/PSP 切换和 Fault 状态寄存器读取顺序。

## 18.4 多核启动时序
**非单核 M7 架构定义项。** 若 SoC 为多核，应另补从核释放、入口设置、同步事件和共享内存初始化顺序。

## 18.5 ENDINIT 保护寄存器写入时序
**不适用于原生 M7。** 若 SoC 自定义了关键寄存器写窗口，可在平台手册中单独给时序图。

## 18.6 Overlay 生效时序
**不适用于原生 M7 内核。** 若平台支持地址重映射/在线标定，应单列系统级时序说明。

## 18.7 软件复位 / 核复位时序
M7 可重点描述 `SYSRESETREQ` 触发路径；若 SoC 还支持局部核复位或调试核复位，则需由平台补充。

# 22. 结语

Cortex-M7 适合作为车规 MCU 的高性能实时控制内核，但其“内核手册”写法不能直接照搬 TriCore。  
最核心的调整是：  
- 用 **Exception/Fault + NVIC** 替换 TriCore 的 Trap 叙事；  
- 用 **MSP/PSP + 异常自动压栈** 替换 CSA 叙事；  
- 用 **MPU + Privileged/Unprivileged** 替换 ENDINIT / 保护集叙事；  
- 将 **Boot、安全、复位树、调试安全、多核** 明确拆到 **SoC 实现层** 去写。  

如果后续你要继续往下做，最合适的下一步通常不是继续“泛泛填充”，而是把这份文稿收敛成：  
1. **对外正式目录版**  
2. **对软件团队可直接使用的章节版**  
3. **对验证/安全团队的检查点版**
