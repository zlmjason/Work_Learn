PROJECT NORTH STAR · 2026.10—2027.05

具身智能视觉随动关节

从现有 AURIX TC3xx、PMSM 与 FreeRTOS 工程出发，逐步构建“端侧视觉AI + Linux/ROS2 + 实时控制MCU”的完整感知—决策—执行闭环。

03 · Responsibility Boundary

AI与实时控制的边界

AI决定“想做什么”，实时MCU决定“能不能做、怎样稳定做，以及异常时怎么办”。

端侧AI / Linux / ROS2

软实时、高计算量、允许迭代

  • 目标检测、识别与持续跟踪
  • 根据像素偏差生成高层目标
  • 系统编排、日志、可视化与模型更新
  • 输出位置、速度、转矩或轨迹参考量
⇄
TC3xx / FreeRTOS

硬实时、确定性、最终安全权

  • 命令有效性、时效性和边界检查
  • 平滑轨迹、位置/速度/FOC闭环
  • 过流、超温、堵转与通信超时保护
  • 即使上位机失效，仍能进入安全状态

05 · Roadmap

从现在到2027年5月的阶段路线

每一阶段只增加一个主要能力，并设置明确“出口”；上一阶段没有闭环，不进入下一阶段。

2026.10—11
PHASE 0

确定边界与硬件条件

把已有资源、缺失硬件和安全边界一次讲清。

本阶段形成

TC3xx型号与开发环境清单；逆变器、编码器、电流采样、通信接口与机械结构清单；系统模块边界；第一版命令/状态接口。

出口：确认电机可安全驱动，确定第一版系统框图和接口边界。
2026.11—12
PHASE 1

TC3xx实时执行层

先让“肌肉与小脑”独立可靠运行。

本阶段形成

PMSM基本控制；编码器与电流反馈；FreeRTOS任务边界；运行/停止/故障状态；本地保护；周期与抖动测量框架。

出口：无上位机参与时，也能稳定控制、受控停止并报告故障。
2027.01
PHASE 2

Windows上位机协同

先验证“目标—执行—状态”闭环。

本阶段形成

Windows C++或Python控制端；CAN/串口/Ethernet通信；目标命令下发；实时状态曲线；序号、时间戳、CRC、心跳和超时机制。

出口：电脑给定目标，TC3xx执行并反馈；断开上位机后安全停机。
2027.02
PHASE 3

Linux与ROS2系统化

把专用Demo升级为机器人软件组件。

本阶段形成

ROS2 C++通信节点；关节状态与控制命令消息；日志与回放；硬件抽象；条件允许时接入ros2_control。

出口：ROS2能查看关节状态、发送目标并诊断通信状态。
2027.03
PHASE 4

视觉闭环与具身应用

让系统从“被控制”变成“自主跟随”。

本阶段形成

摄像头采集；目标检测与跟踪；像素偏差到关节目标的转换；目标丢失策略；摄像头随PMSM转动形成视觉反馈。

出口：目标左右移动时，关节自主跟随并保持目标接近画面中心。
2027.04
PHASE 5

迁移到端侧AI平台

证明架构可迁移，不停留在Windows。

本阶段形成

选择Jetson或RK3588；ARM64重新编译；Linux通信驱动；TensorRT或RKNN推理后端；目标板延迟、负载和温度测试。

出口：同一应用在真实端侧板运行，TC3xx协议与控制固件保持稳定。
2027.05
PHASE 6

工程验证与求职包装

把“能跑”变成“能证明”。

本阶段形成

端到端延迟与抖动报告；长时间运行；故障注入；架构与接口文档；项目仓库；演示视频；四个可深挖面试案例。

出口：形成可投递、可演示、可复盘、可继续扩展的完整项目。
06 · Final Demo

最终演示必须讲清五个场景

演示重点不是模型有多复杂，而是整条物理链路的实时性、协同性和故障边界。

正常跟随

人或目标左右移动，摄像头关节自动跟随并保持居中。

状态可视

ROS2实时显示目标误差、关节角度、转速、电流和系统状态。

目标丢失

短时丢失进入等待，超时后停止或平滑回到中位。

通信中断

拔掉上位机链路，TC3xx独立识别超时并进入安全状态。

非法命令

上位机给出越界目标，TC3xx完成限幅、拒绝或降级处理。

平台迁移

从Windows切换至ARM64端侧板，上层逻辑复用、平台后端替换。

08 · Scope Control

第一版做什么，不做什么

范围稳定比堆叠功能重要。先把一条链路做深，再扩展自由度、传感器和算法复杂度。

第一版必须完成

一轴、一个目标、一条完整闭环

  • 一个摄像头和一个PMSM旋转关节
  • 目标检测、跟踪与关节目标生成
  • ROS2/通信/TC3xx/PMSM全链路
  • 超时、越界、目标丢失与本地保护
  • 延迟、抖动、状态与故障可观测
第一版暂不展开

不让目标被复杂度淹没

  • 完整人形机器人或多关节动力学
  • 从零训练VLA或机器人基础模型
  • 用AI替代FOC/PID等确定性控制
  • 同时适配多块AI芯片和多种总线
  • 一开始就追求双轴云台或复杂机械臂
