# FreeRTOS × TC397 板级实践跟踪清单

## 核心问题

如何保证每个 RTOS 知识点都有"看得见、量得出"的板级证据，而不是停留在代码阅读和口头理解？本项目需要一份可执行、可验收、与知识支点一一对应的实验清单。

## 结论

- 每个实验有唯一 ID、明确的验收判据、以及它验证的知识支点。
- 实验遵循"先预测、再测量、后解释"：动手前写下预期现象，测量后对比差异，差异才是学习发生的地方。
- 实验代码与配置改动必须提交到工程仓库（`TC397_FreeRTOS`），commit message 注明实验 ID。
- 破坏性实验（栈溢出、CSA 耗尽、故障注入）单独分支或临时提交，验证后恢复基线。

### 实验纪律

1. **预测先行**：执行前写下"预期看到什么"，避免事后合理化。
2. **证据留痕**：记录关键数值、寄存器值、截图路径或 commit。
3. **差异解释**：预期与实测不符时，先解释差异，再决定是否修改认知。
4. **基线恢复**：破坏性实验结束后恢复可运行基线，并再次验证。
