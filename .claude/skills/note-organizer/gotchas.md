# Note Organizer — 常见陷阱与失败模式

## 1. 不要只看文件名判断层次

文件名可能含糊，必须读内容才能确定。例如：

- `SPI.md` 可能是硬件 SPI，也可能是 AUTOSAR SPI Stack。
- `IPC.md` 可能是硬件核间通信，也可能是 AUTOSAR IOC。

**对策**：读取文件前 100 行和标题，确认核心主题。

## 2. 不要把跨层次文件硬塞进一个目录

如果文件同时涉及硬件 SPI、AUTOSAR SPI Driver 和 MCAL 配置，不要只放在一层。应：

- 选择最核心的一层归档
- 或者建议用户拆分成多篇

## 3. 避免覆盖已有文件

移动前先用 `ls` 或 `git status` 检查目标位置。如果已存在同名文件：

- 不要直接覆盖
- 询问用户是否合并、重命名或归档旧版本

## 4. 不要自动创建深层目录

CLAUDE.md 的目录结构比较固定。如果目标子目录不存在，先询问用户是否新建，避免破坏结构。

## 5. 中文文件名中的特殊字符

Windows / Git Bash 下中文文件名可能显示为转义序列。使用双引号包裹路径：

```bash
mv "原文件名.md" "目标目录/新文件名.md"
```

## 6. 附件不要和 md 一起乱放

如果 md 引用了本地图片/PDF，应将附件一起移动到 `99_Attachments_附件/` 对应子目录，并更新 md 中的相对链接。

## 7. 不要破坏 Obsidian 双链

如果原文件被其他笔记通过 `[[旧文件名]]` 链接，移动后双链会失效。整理后应：

- 提醒用户检查双链
- 必要时批量更新链接

## 8. 临时文件不要急着归档

如果文件明显是草稿、待补充、或不完整，建议先留在 `00_Inbox_临时收集/`，等成熟后再归档。

## 9. 命名不要太长

虽然下划线连接可以很长，但建议文件名控制在 80 个字符以内，便于阅读和显示。

## 10. 执行后必须确认

每次移动后用 `git status --short` 确认结果，并向用户汇报原路径和新路径。
