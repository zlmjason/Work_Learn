# MCU Note Creator — 陷阱与常见失败模式

本文件记录创建 MCU 知识库笔记时容易犯的错误（Gotchas）。

---

## 1. 文件名带空格

**表现**：`AURIX TC3xx SPI Config.md`

**后果**：Obsidian 和 Git 都可能出问题，违反项目规范。

**正确做法**：全部用下划线，如 `AURIX_TC3xx_Periph_Comm_SPI_Config.md`。

---

## 2. 技术术语中文化

**表现**：文件名或正文里写 "串行外设接口配置"、"控制器局域网协议"

**后果**：检索困难，违反项目写作风格。

**正确做法**：技术术语保留英文，如 `SPI`、`CAN-FD`、`Cortex-M7`、`AUTOSAR`。正文首次出现可补充中文解释。

---

## 3. 目录放错层

**表现**：把 AUTOSAR CAN Stack 笔记放到 `01_Hardware_硬件层/05_Peripherals/01_Communication/03_CAN_CANFD/`

**后果**：同一主题在 Hardware 和 Middleware 两层产生混淆。

**正确做法**：
- 硬件寄存器、时序、电气 → Hardware 层
- AUTOSAR MCAL/BSW 模块 → Middleware / AUTOSAR 层
- 文件名前缀必须体现层次：`HW_Periph_Comm_CAN_...` vs `AUTOSAR_Comm_CAN_...`

---

## 4. 缩写未大写

**表现**：文件名写 `Aurix_tc3xx_spi_config.md` 或 `autosar_comm_can_stack.md`

**正确做法**：英文缩写统一大写：`AURIX_TC3xx`、`SPI`、`CAN`、`AUTOSAR`。

---

## 5. 直接删除旧笔记

**表现**：用户说 "这篇旧笔记没用了，删掉吧"，直接 `rm`。

**后果**：知识库历史丢失，Obsidian 双链可能失效。

**正确做法**：先移动到 `90_Archive_归档/`，保留原始路径信息。

---

## 6. 遗漏必要章节

**表现**：笔记只有标题和正文，缺少 `## 核心问题`、`## 结论` 等结构。

**后果**：不符合项目 9 段式模板，降低可维护性。

**正确做法**：按模板创建，暂时没有内容可写 "待补充"。

---

## 7. 破坏 Obsidian 双链

**表现**：把 `[[AURIX TC3xx]]` 改成 `[AURIX TC3xx]` 或修改链接目标文件名后未更新双链。

**正确做法**：保留 `[[...]]` 格式；重命名文件时同步检查双链引用。

---

## 8. 代码块不标注语言

**表现**：

```
// 这是一段 C 代码
```

**正确做法**：必须标注语言：

```c
// 这是一段 C 代码
```

---

## 9. 附件乱放

**表现**：图片直接放在笔记同级目录。

**正确做法**：附件统一放入 `99_Attachments_附件/`。

---

## 10. 未区分临时笔记和正式笔记

**表现**：把未经整理的草稿直接放入正式目录。

**正确做法**：临时/未整理内容先放入 `00_Inbox_临时收集/`，整理后再迁移。
