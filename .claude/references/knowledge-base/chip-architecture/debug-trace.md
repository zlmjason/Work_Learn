# MCU 调试与追踪系统 — 验证指南

调试和追踪是芯片验证的核心手段。车规 MCU 通常支持多种调试接口和追踪机制，从基本的 JTAG/SWD 到高级的系统级追踪（ETM/ITM/MTB）。

## 调试接口

### 1. JTAG（Joint Test Action Group）

**关键参数：**
- 信号线：TCK、TMS、TDI、TDO、TRST（可选）
- 时钟频率：通常 1~20MHz
- 菊花链：支持多个芯片级联

**测试要点：**
- [ ] 验证 JTAG IDCODE 读取
- [ ] 验证边界扫描（Boundary Scan）功能
- [ ] 验证 JTAG 链的完整性（所有 TAP 可访问）
- [ ] 验证 JTAG 调试（断点、单步、寄存器读写）
- [ ] 验证 JTAG 频率上限（高频下的信号完整性）

### 2. SWD（Serial Wire Debug）

**关键参数：**
- 信号线：SWCLK、SWDIO（2 线）
- 时钟频率：通常 1~50MHz
- 协议：基于 ARM CoreSight DAP

**测试要点：**
- [ ] 验证 SWD 连接建立（Switching Sequence）
- [ ] 验证 SWD 调试（断点、单步、寄存器读写）
- [ ] 验证 SWD 与 JTAG 的切换（如果支持）
- [ ] 验证 SWD 频率上限
- [ ] 验证 SWD 在低功耗模式下的连接保持

**SWD vs JTAG 对比：**
| 特性 | JTAG | SWD |
|------|------|-----|
| 引脚数 | 5 | 2 |
| 速度 | 中等 | 快 |
| 菊花链 | 支持 | 不支持 |
| 调试功能 | 完整 | 完整 |
| 推荐场景 | 板级测试 | 日常调试 |

### 3. 调试保护

车规 MCU 必须支持调试保护，防止恶意读取程序代码：

**保护等级：**
- Level 0：无保护（开发阶段）
- Level 1：调试受限（可连接但无法读取 Flash）
- Level 2：调试完全禁用（量产阶段，不可恢复）

**测试要点：**
- [ ] 验证各级保护下的调试行为
- [ ] 验证保护等级切换（Level 0 → 1 → 2）
- [ ] 验证 Level 2 的不可逆性（确认无法降级）
- [ ] 验证保护下的 Flash 读取限制
- [ ] 验证保护下的 RAM 读取限制

## 追踪机制

### 1. ETM（Embedded Trace Macrocell）

**关键参数：**
- 追踪端口：4-bit / 8-bit / 16-bit 并行端口
- 时钟频率：与 CPU 同频或半频
- 追踪内容：指令流、数据访问、异常事件

**测试要点：**
- [ ] 验证 ETM 追踪端口的信号完整性
- [ ] 验证指令追踪（PC 值序列）
- [ ] 验证数据追踪（读/写地址和数据）
- [ ] 验证触发条件（特定地址/数据触发追踪）
- [ ] 验证追踪缓冲区溢出处理

### 2. ITM（Instrumentation Trace Macrocell）

**关键参数：**
- 接口：SWO（Serial Wire Output）单线
- 用途：软件日志输出（printf 调试）
- 带宽：通常 1~50Mbps

**测试要点：**
- [ ] 验证 ITM 端口配置（波特率分频）
- [ ] 验证软件日志输出（`ITM_SendChar`）
- [ ] 验证 ITM 与 SWD 的共享（SWD 和 SWO 复用 SWCLK）
- [ ] 验证 ITM 的 32 个 stimulus 端口

### 3. MTB（Micro Trace Buffer）

**关键参数：**
- 用途：低成本指令追踪（使用 SRAM 作为循环缓冲区）
- 容量：通常 1KB ~ 4KB
- 无需外部追踪端口

**测试要点：**
- [ ] 验证 MTB 缓冲区的循环覆盖
- [ ] 验证 MTB 的触发和停止条件
- [ ] 验证 MTB 数据的解码（需要地址到符号的映射）

### 4. DWT（Data Watchpoint and Trace）

**关键参数：**
- 比较器数量：通常 4 个
- 用途：数据观察点、PC 采样、性能计数

**测试要点：**
- [ ] 验证数据观察点（特定地址读写时触发）
- [ ] 验证 PC 采样（周期性记录 PC 值，用于性能分析）
- [ ] 验证性能计数器（时钟周期、 folded 指令、加载存储单元停顿等）

## 调试与低功耗模式

**关键问题：**
调试器连接时，MCU 不能进入 Deep-Sleep/Stop 模式，否则调试连接会断开。

**解决方案：**
- 调试器通过 DHCSR.C_DEBUGEN 阻止 CPU 进入低功耗模式
- 或使用 DBGMCU_CR 配置低功耗模式下的调试行为

**测试要点：**
- [ ] 验证调试连接时的低功耗模式行为
- [ ] 验证断点触发后的唤醒
- [ ] 验证单步执行跨越 WFI/WFE 指令

## 车规特殊要求

### 1. 调试安全
- **调试接口禁用**：量产阶段必须禁用调试接口（Level 2 保护）
- **调试审计**：记录调试接口的使用历史（用于安全审计）
- **安全调试**：仅在安全认证后允许调试（如通过 HSM 验证）

### 2. 故障诊断
- **故障寄存器**：CoreSight 提供详细的故障信息（CFSR、HFSR、MMFAR、BFAR）
- **故障记录**：在 Flash/Backup SRAM 中记录故障现场
- **故障分析**：通过追踪数据重建故障发生前的执行流
