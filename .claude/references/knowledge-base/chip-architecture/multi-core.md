# MCU 多核架构 — 验证指南

现代车规 MCU 越来越多地采用多核架构，以满足功能安全（Lockstep）、性能（并行处理）和功耗（异构计算）的需求。多核验证是芯片验证中最复杂的领域之一。

## 多核架构类型

### 1. 同构多核（Homogeneous Multi-Core）

**特征：** 所有核心相同，对称处理

**典型实现：**
- 双核 Cortex-M7（如某些高端车身控制器）
- 双核 Cortex-R52（Lockstep 模式）
- 三核 TriCore（AURIX TC3xx，1+1 Lock + 1 应用核）

**测试要点：**
- [ ] 验证各核心独立运行
- [ ] 验证核间中断（Inter-Processor Interrupt, IPI）
- [ ] 验证共享资源竞争（总线仲裁、SRAM Bank 访问）
- [ ] 验证缓存一致性（如果支持硬件一致性）

### 2. 异构多核（Heterogeneous Multi-Core）

**特征：** 核心类型不同，分工协作

**典型实现：**
- Cortex-A53（应用处理）+ Cortex-M7（实时控制）
- Cortex-R52（安全关键）+ Cortex-M33（通用控制）
- TriCore（主核）+ GTM（定时器协处理器）

**测试要点：**
- [ ] 验证异构核心的协同启动
- [ ] 验证核间通信（共享内存、消息传递）
- [ ] 验证异构核心的时钟域 crossing
- [ ] 验证异构核心的电源域独立控制

### 3. Lockstep 双核

**特征：** 两个核心执行相同指令流，输出比较

**典型实现：**
- AURIX TC3xx：1+1 Lockstep
- TI TMS570：双核 R5F Lockstep
- NXP S32K3：可选 Lockstep M7

**测试要点：**
- [ ] 验证 Lockstep 比较逻辑（注入单比特错误，验证检测）
- [ ] 验证 Lockstep 故障后的安全响应（复位/进入安全模式）
- [ ] 验证 Lockstep 模式下的性能（通常延迟增加 1~2 周期）
- [ ] 验证 Lockstep 模式下的调试限制（两个核心必须同步）
- [ ] 验证 Split 模式 ↔ Lockstep 模式切换（如果支持）

## 核间通信机制

### 1. 共享内存（Shared Memory）

**实现方式：**
- 多核共享 SRAM Bank
- 通过 MPU 划分各核的私有区域和共享区域
- 使用信号量（Semaphore）保护临界区

**测试要点：**
- [ ] 验证共享内存的读写正确性（多核并发访问）
- [ ] 验证信号量机制（原子操作、自旋锁）
- [ ] 验证缓存一致性（多核 Cache 同步）
- [ ] 验证共享内存的 ECC（多核同时访问时的 ECC 处理）

**常见缺陷：**
- 未使用原子操作保护共享变量，导致数据竞争
- Cache 不一致（一核修改数据，另一核读到旧值）
- 死锁（两个核互相等待对方释放信号量）

### 2. 消息传递（Message Passing）

**实现方式：**
- 邮箱（Mailbox）：固定大小的消息队列
- 门铃（Doorbell）：中断通知机制

**测试要点：**
- [ ] 验证邮箱的写入/读取（FIFO 顺序）
- [ ] 验证邮箱溢出处理（满时写入的行为）
- [ ] 验证门铃中断（一核写入，另一核接收中断）
- [ ] 验证消息传递的延迟（从中断到 ISR 执行）

### 3. 核间中断（IPI）

**实现方式：**
- 专用硬件寄存器触发对方中断
- 如 AURIX 的 SRI（Shared Resource Interconnect）中断

**测试要点：**
- [ ] 验证 IPI 的触发和响应
- [ ] 验证 IPI 的优先级（与外部中断的优先级关系）
- [ ] 验证 IPI 的嵌套（高优先级 IPI 打断低优先级 IPI）

## 资源分配与仲裁

### 1. 总线仲裁

**仲裁策略：**
- Round-Robin：轮询，公平分配
- Priority：固定优先级，高优先级核优先
- TDMA：时分复用，确定性分配

**测试要点：**
- [ ] 验证总线仲裁的公平性（各核带宽分配）
- [ ] 验证总线仲裁的确定性（TDMA 模式下时隙固定）
- [ ] 验证总线占用时间（防止一核长期占用总线）
- [ ] 验证总线错误（非法访问时的响应）

### 2. 外设分配

**分配方式：**
- 静态分配：外设固定绑定到某一核
- 动态分配：外设可被多核共享（需仲裁）

**测试要点：**
- [ ] 验证静态分配外设的独占访问
- [ ] 验证动态分配外设的仲裁机制
- [ ] 验证外设切换（从一核切换到另一核）

## 启动与同步

### 1. 多核启动

**启动流程：**
```
POR 复位 → 主核（Core 0）启动 → 初始化系统 → 唤醒从核（Core 1/2/3）
                                   ↓
                              从核等待启动信号
                                   ↓
                              从核开始执行代码
```

**测试要点：**
- [ ] 验证主核的启动时序（从核是否在主核初始化完成后才启动）
- [ ] 验证从核的启动地址（通过启动寄存器配置）
- [ ] 验证启动失败的处理（从核未响应时的超时处理）
- [ ] 验证热复位（仅复位单个核心，不影响其他核）

### 2. 核间同步

**同步机制：**
- 屏障（Barrier）：所有核到达某点后继续
- 信号量（Semaphore）：保护临界区
- 事件标志（Event Flag）：通知其他核事件状态

**测试要点：**
- [ ] 验证屏障同步（所有核同时到达屏障）
- [ ] 验证信号量的获取/释放（原子操作）
- [ ] 验证事件标志的设置/清除

## 功能安全要求

### 1. 核隔离
- **内存隔离**：各核的私有内存不可被其他核访问
- **外设隔离**：各核的外设不可被其他核访问
- **中断隔离**：各核的中断独立管理

### 2. 故障检测
- **Lockstep 比较**：双核输出不一致时触发故障
- **总线监控**：检测非法访问和总线错误
- **看门狗**：每核独立看门狗，防止单核死锁

### 3. 故障响应
- **单核复位**：仅复位故障核，不影响其他核
- **系统复位**：所有核同时复位
- **安全状态**：进入预定义的安全状态（如关闭输出）

## 典型多核 MCU 案例

### Infineon AURIX TC3xx
- 核心：1+1 Lockstep TriCore + 1 应用 TriCore
- 特色：SRI 总线、GTM 定时器协处理器、Safety Monitor
- 应用：动力域、底盘域

### NXP S32K3
- 核心：双核 Cortex-M7（可选 Lockstep）
- 特色：每个核独立 MPU、核间邮箱、硬件信号量
- 应用：车身域、区域控制器

### Renesas RH850/U2A
- 核心：双核 RH850 G3M + G3H
- 特色：核间中断、共享内存、硬件锁
- 应用：车身域、网关
