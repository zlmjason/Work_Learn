# purpose-driven-book-study 陷阱与失败模式

## 方法论类

1. **按章节顺序机械推进**
   症状：从第 1 页开始线性读。违背目的驱动的根本设定。
   纠正：目录是索引不是顺序；按问题/依赖/工作价值排序，除非用户明确要通读。

2. **把摘要当精读**
   症状：每个小节都产出一篇"讲了什么"的浅总结。
   纠正：阶段收尾才落盘（能力建成为标志）；单元级别只在对话里讨论。最低质量线见模板文件"Minimum quality bar"。

3. **观点/解读/延伸/验证混为一谈**
   症状：把"我的推断"说得像"书上写的"，或把"书上结论"直接当成"用户系统上成立"。
   纠正：四类标签显式分离；跨架构迁移必须显式说明差异。

4. **二手资料覆盖一手规范**
   症状：教科书说法与厂商 RM/标准冲突时，随口用教科书覆盖。
   纠正：规范性文档优先；冲突必须显式呈现，附版本与条件。

## 本库环境类

5. **对话里用 LaTeX/Mermaid**
   症状：`$$...$$` 和 ```mermaid 在用户端显示为源码（LRN-20260815-001）。
   纠正：公式纯文本、图用 ASCII/表格；落盘笔记不受此限。

6. **不确认就动手**
   症状：直接创建专区、批量落盘、改路线。
   纠正：先列方案等拍板（LRN-20260717-001）；追求一次性成功。

7. **落盘后绕过 doc-review**
   症状：笔记不合命名/模板规范，事后返工。
   纠正：hook 已自动化（PostToolUse），看到注入的问题立即修。

8. **素材与产出混放**
   症状：MinerU 原始解析放笔记层，或精读笔记放进附件目录。
   纠正：素材进 `99_Attachments_附件`、产出进笔记层；引用单向：笔记 → 附件（§9.1 规则 12）。

9. **疑点不分级**
   症状：拿不准的芯片参数/寄存器事实说得跟确定一样。
   纠正：✅/🟡/❓ 显式标注；❓ 的写明"需查 XX 手册确认"。

10. **用户复述时一味附和**
    症状：用户问"对吧"就直接说对。
    纠正：严格验收是这个 skill 的核心价值；偏差要指出错在哪、为什么错（参考实现：SoC 会话中"频率瓶颈"纠正）。
