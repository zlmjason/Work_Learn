# Find Skills — 陷阱与常见失败模式

本文件记录查找和安装 Skill 时容易犯的错误（Gotchas）。

---

## 1. 把通用问题误判为需要 Skill

**表现**：用户问一个简单问题（如 "git 怎么撤销上一次提交"），就想去搜 Skill。

**正确做法**：先判断问题是否足够复杂、是否重复出现、是否有现成的通用工具链。简单问题直接用通用能力回答。

---

## 2. 搜索词太宽泛

**表现**：`npx skills find testing` 返回太多不相关结果。

**正确做法**：使用具体关键词，如 `npx skills find react testing` 或 `npx skills find jest coverage`。

---

## 3. 未确认就安装 Skill

**表现**：看到 Skill 名字相关就直接 `npx skills add ...`。

**正确做法**：先向用户展示 Skill 名称、作用、安装命令和链接，获得同意后再安装。

---

## 4. 忽略 `-g` 和 `-y` 的含义

**表现**：安装时不加 `-g` 导致 Skill 只装在当前目录，或不加 `-y` 导致需要用户多次确认。

**正确做法**：全局安装用 `-g`，自动确认用 `-y`，但安装前仍需获得用户授权。

---

## 5. 未验证 Skill 是否可用

**表现**：安装后没有检查 Skill 是否真正工作。

**正确做法**：安装后简要说明 Skill 路径，并建议用户测试一个简单命令。

---

## 6. 重复安装相同 Skill

**表现**：用户已经安装过某 Skill，再次执行安装。

**正确做法**：安装前可先运行 `npx skills check` 查看已安装 Skill 列表。

---

## 7. 网络问题导致安装失败

**表现**：`npx skills add` 因网络或 GitHub 访问失败。

**正确做法**：提示用户检查网络、GitHub 可访问性，或考虑手动 clone 到 skills 目录。

---

## 8. 不知道本地 Skill 和远程 Skill 的区别

**表现**：用户想找的功能其实已经在 `.claude/skills/` 里，但仍去搜远程。

**正确做法**：搜索前先检查本地 Skill 列表，优先使用项目内 Skill。
